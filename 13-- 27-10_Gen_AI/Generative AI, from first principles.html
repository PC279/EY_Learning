Part I

Foundations

Before any model names: what “generating” means, where it sits in AI, how anything becomes numbers, and how a machine learns at all.

1.1What it means to generate

Traditional machine learning is mostly discriminative: given an input, predict a label. Is this email spam? Is this transaction fraud? What will demand be next month? Mathematically the model learns p(label | data), a rule for drawing a boundary between classes.

A generative model learns something much richer: p(data) itself, the probability of the data. If you know how likely every possible sentence or image is, you can do two things a classifier cannot. You can score any example (“how typical is this?”), and you can sample: draw brand-new examples that follow the same patterns as the training data but were never in it.

First principle

“Generating” is sampling from a learned probability distribution. Creativity, in this technical sense, comes from randomness constrained by learned structure. Remove the randomness and a model always produces the same output; remove the structure and you get noise.

Why is this hard? Because real data lives in absurdly large spaces. A 512 × 512 colour image is 786,432 numbers, each from 0 to 255, so the number of possible images is 256786,432. Almost all of them are static. The real photos form a thin, curved “surface” inside that space, and the whole art of generative AI is learning where that surface is and how to land on it.

1.2Where generative AI sits

The four source reports agree on the hierarchy, and it is worth fixing firmly in mind because the terms are often used loosely.

Artificial intelligence is the broad goal of systems that do tasks needing intelligence. Early AI was rule-based: experts wrote if–then rules by hand. Machine learning replaced hand-written rules with rules learned from data. Deep learning is machine learning with neural networks many layers deep, which can learn their own features (edges, shapes, grammar) instead of being told what to look for. Generative AI is the part of deep learning aimed at producing content.

A foundation model is a very large model trained on broad data so it can be adapted to many tasks: summarising, translating, coding, answering questions. GPT, Claude, Gemini and Llama are foundation models for language; Stable Diffusion is one for images. A large language model (LLM) is a foundation model whose main medium is text.

1.3Everything becomes numbers

A neural network can only do arithmetic. So the first step for any kind of content is to turn it into arrays of numbers, called tensors.

  • Text is split into tokens (whole words, pieces of words, punctuation), and each token gets an integer ID from a fixed vocabulary, typically 32,000 to 200,000 entries.
  • Images are height × width × 3 grids (red, green, blue). Modern image generators usually work on a compressed version called a latent, which we will meet in Part V.
  • Audio is a waveform: an amplitude measured 16,000 to 48,000 times per second. Models often work on a spectrogram (frequency against time) or on compressed audio tokens instead.
  • Code is text with stricter rules, so code models are language models trained heavily on code.

1.4How a machine learns

Strip away the mystique and a neural network is a function with adjustable numbers inside, called parameters or weights. The simplest possible “network” is one weight:

prediction = w · xone input x, one weight w, one output

Learning means finding the value of w that makes predictions match reality. To do that you need a single number that says how wrong you are, the loss. For one example with input x = 2 and correct answer y = 6, the squared error is:

L(w) = (w·x − y)²zero when the prediction is perfect, growing fast as it gets worse

Calculus tells you which way is downhill. The gradient ∂L/∂w = 2(w·x − y)·x is the slope of the loss. Step the weight a little in the opposite direction, scaled by a learning rate η, and repeat. That is gradient descent:

start w = 0 prediction 0 loss 36.00 gradient 2(0−6)(2) = −24
step 1 w = 0 − 0.05·(−24) = 1.20 prediction 2.4 loss 12.96
step 2 w = 1.2 − 0.05·(−14.4) = 1.92 prediction 3.84 loss 4.67
… w → 3.00 prediction 6.00 loss → 0

Try it below. Notice the two classic failure modes: a learning rate that is too small crawls, and one that is too large overshoots and can diverge.

Fig 1.5 Gradient descent on L(w) = (2w − 6)². Each step moves w by −η × slope. Above η = 0.25 the steps overshoot by more than they correct, and the loss explodes.

A real network has billions of weights instead of one, and millions of examples instead of one, but the idea is identical. Backpropagation is simply the efficient bookkeeping, using the chain rule of calculus, that computes the gradient for every weight in one backward sweep through the network. Stochastic gradient descent does this on small random batches of data, and modern optimisers such as Adam adapt the step size per weight.

1.5Neural networks, depth and scale

Stack many simple units and you get a neural network. Each neuron computes a weighted sum of its inputs plus a bias, then applies a non-linear activation such as ReLU (max(0, z)). Without the non-linearity, any stack of layers would collapse into a single linear function; with it, a deep network can approximate extremely complicated functions.

h = activation(W·x + b)one layer: a matrix multiply, a shift, a bend. A deep network repeats this dozens or hundreds of times.

Three facts explain most of the progress since 2017:

  1. Scale works. Loss falls smoothly and predictably as you increase parameters, data and compute together, a relationship called a scaling law. GPT-3 (2020) had 175 billion parameters; today’s frontier models are trained on many trillions of tokens.
  2. Self-supervision removes the labelling bottleneck. “Predict the next word” or “predict the noise I added” needs no human labels: the data labels itself, so you can train on most of the public internet.
  3. One architecture, many modalities. The Transformer (Part III) turned out to work for text, images, audio, video and code alike.

All four source reports describe the same three-phase life cycle, which this guide follows: train a foundation model on huge data, tune it for specific tasks or behaviour, then generate in response to prompts.

Common misconception

A model does not store its training data like a database and look things up. It stores parameters that compress statistical patterns. That is why it can generalise to new inputs, and also why it can produce fluent text that is wrong: it reproduces patterns, not verified facts. (Models can still memorise some text verbatim, especially passages repeated many times in the training data, which matters for privacy and copyright.)

Part II

How language models work

Tokens, vectors, probabilities and sampling. By the end of this part you can explain exactly what happens when a chatbot writes one word.

2.1Tokens: the units of text

Models do not read characters or whole words; they read tokens. A tokenizer is built before training with an algorithm such as byte-pair encoding (BPE): start from single bytes, then repeatedly merge the most frequent adjacent pair into a new token, until the vocabulary reaches the target size. Common words end up as one token; rare words are split into familiar pieces.

Generative AI is unbelievably useful, even in Ouagadougou.

An illustrative split (exact boundaries depend on the tokenizer). Leading spaces usually belong to the token that follows them.

  • Rule of thumb for English: 1 token ≈ 4 characters ≈ ¾ of a word. A 1,000-word essay is roughly 1,300 tokens.
  • Prices, speed and the context window (how much text a model can consider at once) are all measured in tokens.
  • Languages and scripts that were rare in the tokenizer’s training data split into more tokens per word, so the same sentence can cost more, and fit less, in Tamil, Hindi or Amharic than in English.
  • Tokenization explains some famous quirks: a model that sees “strawberry” as two or three tokens never directly sees its individual letters, so counting letters is surprisingly hard for it.

2.2Embeddings: meaning as geometry

A token ID is just an index; the number 6975 is not “closer” to 6976 in meaning. So the first layer of a language model is an embedding table: a learned vector (a list of, say, 4,096 numbers) for every token. Training pushes tokens used in similar contexts to have similar vectors, so meaning becomes position.

Similarity between two vectors is usually measured with the cosine similarity, the cosine of the angle between them:

cos(a, b) = (a · b) / (‖a‖ ‖b‖)1 means same direction, 0 unrelated, −1 opposite. This one formula powers semantic search and retrieval (Part IV).

The famous example is that vector(king) − vector(man) + vector(woman) lands near vector(queen). It is a lovely illustration that directions can carry meaning, but treat it as a cartoon: in modern models such analogies are approximate and inconsistent. What matters in practice is that “similar meaning ⇒ nearby vectors”, which is why the same idea is used for search, recommendations and RAG.

Going deeper

Inside a Transformer, a token’s vector does not stay fixed. Each layer rewrites it using context, so “bank” in “river bank” and in “bank loan” starts identical and ends far apart. These are contextual embeddings, and they are what embedding models (the ones you call for RAG) actually output, usually pooled into one vector per passage.

2.3Predicting the next token

Here is the core trick of every GPT-style model, and it rests on one rule of probability. The chain rule says the probability of a whole sequence factorises into a product of next-token probabilities:

P(w₁, w₂, …, wₙ) = P(w₁) · P(w₂ | w₁) · P(w₃ | w₁, w₂) · … · P(wₙ | w₁ … wₙ₋₁)exact, not an approximation: any distribution over sequences can be written this way

So if a model can predict “what comes next, given everything so far”, it can represent the probability of any text, and it can generate text by predicting, sampling, appending and repeating. Models built this way are called autoregressive: “auto” (self) + “regressive” (using previous outputs to predict the next).

P(“I love machine learning”)
= P(I) × P(love | I) × P(machine | I love) × P(learning | I love machine)

This explains several things users notice. Text streams out word by word because it is produced word by word. Longer answers cost more because each token is one full pass through the network. And a model can “talk itself into” an error: once a wrong token is sampled, everything after it is conditioned on that mistake.

2.4Logits, softmax, temperature and sampling

For each step the network outputs one raw score per vocabulary entry, called a logit. Logits can be any real number. The softmax function turns them into probabilities that are positive and sum to one, and a temperature T controls how peaked that distribution is:

P(token i) = ezᵢ / T / Σⱼ ezⱼ / Tzᵢ is the logit. T < 1 sharpens the distribution, T > 1 flattens it, and T → 0 always picks the top token.

2.5How a language model is trained

Training uses the same next-token setup, but scores the model on the token that actually came next in real text. The loss is cross-entropy: the negative log of the probability the model gave to the correct token.

L = − log P(correct next token | previous tokens)averaged over every position of every training text
model gives the right token p = 0.85 → loss = −ln 0.85 = 0.16 (good)
model gives the right token p = 0.05 → loss = −ln 0.05 = 3.00 (bad)
model gives the right token p → 0 → loss → ∞ (confidently wrong is punished hardest)

Two details make this efficient. With teacher forcing, the model is always fed the true previous tokens during training (not its own guesses), so all positions of a sequence are scored in parallel in one forward pass. And because the loss is a log-probability, its exponential has a friendly meaning, perplexity: perplexity = eaverage loss. A perplexity of 7.4 (average loss 2.0) means the model is, on average, as uncertain as if it were choosing uniformly among about 7 tokens.

First principle

To predict the next word of a physics textbook, a court judgment or a Python file well, a model is pushed to learn physics, legal reasoning and programming patterns. Nobody programs those skills in. They emerge because they reduce next-token loss. This is why such a simple objective produces such general capabilities, and also why the model’s “knowledge” is only as good as the text it learned from.

Part III

The Transformer

The architecture behind GPT, Claude, Gemini, Llama, most modern image and video models, and code assistants. One mechanism, attention, does the heavy lifting.

3.1The problem attention solves

To predict the next word you need context from anywhere earlier in the text. In “The animal didn’t cross the street because it was too tired”, the word that tells you what “it” means is six words back. Before 2017 the standard tool was the recurrent neural network (RNN), which reads one token at a time and squeezes everything so far into a single running memory vector. That design has two problems: information from far back fades as it is overwritten, and step t cannot start until step t − 1 finishes, so training cannot be parallelised across a sequence.

The 2017 Google paper Attention Is All You Need removed recurrence entirely. In a Transformer, every token looks directly at every other (permitted) token in one step, and all positions are processed in parallel on a GPU. That single change made training on internet-scale text practical.

3.2Self-attention, step by step

Think of a library. You arrive with a query (what you are looking for). Each book has a key on its spine (what it is about) and value inside (its content). You compare your query with every key, decide how relevant each book is, and walk away with a blend of the contents, weighted by relevance.

Self-attention does exactly that for every token at once. Each token’s current vector x is multiplied by three learned matrices to produce its query, key and value:

q = x·WQ k = x·WK v = x·WVthree different “views” of the same token, learned during training

Then, with all tokens stacked into matrices Q, K and V:

Attention(Q, K, V) = softmax( Q·Kᵀ / √dk ) · VQ·Kᵀ: how well each query matches each key · ÷√dₖ: keep scores in a sane range · softmax: turn scores into weights summing to 1 · ×V: blend the values

Why divide by √dk? If the entries of q and k are roughly independent with variance 1, their dot product over dk dimensions has variance dk. With dk = 128 scores would be spread over a range of about ±30, softmax would put almost all weight on one token, and gradients through it would vanish. Dividing by √dk brings the variance back to 1.

A worked example you can check by hand

Three tokens with 2-dimensional keys and values. The current token (“it”) has query q = [2, 0.5].

keys cat [2, 0] mat [0, 2] it [1, 1]
values cat [1, 0] mat [0, 1] it [0.5, 0.5]

scores q·k/√2 cat (4.0)/1.414 = 2.83 mat (1.0)/1.414 = 0.71 it (2.5)/1.414 = 1.77
softmax cat 0.682 mat 0.082 it 0.236 (sum = 1)
output = 0.682·[1, 0] + 0.082·[0, 1] + 0.236·[0.5, 0.5] = [0.80, 0.20]

The new vector for “it” is now mostly made of “cat”. After this layer, the token literally carries information about what it refers to. The desk below runs a real (hand-made) attention head over our sentence. Pick a query word and watch its faders.

First principle

Attention is a content-based, learned, soft lookup. “Content-based” because relevance comes from comparing vectors, not from position. “Learned” because WQ, WK and WV are trained. “Soft” because the result is a weighted blend rather than one hard choice, which keeps everything differentiable so gradient descent can train it.

3.3Masks, heads and position

Causal masking

A model that generates left to right must not peek at the future during training, or predicting the next token would be trivial. Decoder models add a causal mask: scores for later positions are set to −∞ before the softmax, so their weights become exactly zero. Encoder models such as BERT, built for understanding rather than generating, let every token see the whole input.

Multi-head attention

One attention pattern can only express one kind of relationship at a time. So each layer runs several heads in parallel (for example 32), each with its own smaller WQ, WK, WV. Researchers have found heads that track the previous token, heads that link pronouns to nouns, and “induction heads” that copy patterns seen earlier in the context. The heads’ outputs are concatenated and mixed by one more matrix.

Positional information

Attention by itself is order-blind: shuffle the tokens and each one gets the same weighted blend. Position has to be injected. The original Transformer added fixed sine-and-cosine patterns to the embeddings (h = e + p, as one source report shows). Most modern LLMs instead use rotary position embeddings (RoPE), which rotate each query and key by an angle proportional to its position, so the dot product depends on the relative distance between tokens. That generalises better and helps context windows be extended.

3.4The full block, stacked

A Transformer layer pairs attention (tokens exchange information) with a feed-forward network (each token is transformed on its own, through a wide hidden layer, typically 4× the model width). Two pieces of plumbing make deep stacks trainable: residual connections, which add each sub-layer’s output to its input so information and gradients have a direct path, and layer normalisation, which keeps the scale of activations stable.

One way to hold it in your head: the residual stream is a shared notebook that runs through the whole model, one page per token. Attention heads read other tokens’ pages and write notes onto the current page; feed-forward layers read the current page and add facts and transformations; the final layer reads the last page and writes down a probability for every possible next token.

3.6Cost: context windows and the KV cache

Every token attends to every earlier token, so the attention work for a sequence of length n grows as n². Doubling the context quadruples that part of the cost. This is the main reason context windows were once 2,048 tokens and why long contexts remain expensive, even though engineering (FlashAttention, sparse and sliding-window attention) has pushed windows to hundreds of thousands or millions of tokens.

During generation there is a big shortcut. When producing token 501, the keys and values of tokens 1–500 have not changed (the causal mask guarantees it), so they are stored in a KV cache and only the new token’s q, k, v are computed. This turns each new step from re-reading the whole prompt into one small update, at the price of memory. Part IX shows how to size that memory.

Part IV

From base model to useful assistant

A pre-trained model predicts text; an assistant follows instructions, uses your documents and tools, and knows when to say “I don’t know”. This part covers how one becomes the other.

4.1Foundation models and scaling

A foundation model, as one source report puts it, learns general representations from massive data and is then adapted to specific uses. The key empirical discovery is that its loss follows scaling laws: smooth power-law improvements as parameters, data and compute grow together. DeepMind’s 2022 “Chinchilla” study found that, for a fixed compute budget, models had been too big for their data; a compute-optimal model should see roughly 20 training tokens per parameter. Since inference is paid on every request, many current models are deliberately trained on far more tokens than that, so a smaller model can be served more cheaply.

Some abilities appear to switch on at scale (multi-step arithmetic, following unusual instructions). Whether these are true “emergent” jumps or smooth improvements that cross a threshold on a pass/fail metric is still debated; for practical purposes, larger and better-trained models are more capable in ways that are hard to predict in advance.

4.2Fine-tuning and alignment

A base model fresh from pre-training is a superb autocomplete. Ask it “What is the capital of France?” and it may continue with “What is the capital of Spain?”, because lists of quiz questions are common on the web. Turning it into an assistant takes further training on much smaller, carefully built data.

  • Supervised fine-tuning (SFT), also called instruction tuning: continue next-token training, but on examples of prompts paired with high-quality responses.
  • Reinforcement learning from human feedback (RLHF): people compare two answers to the same prompt; a reward model is trained to predict their preference; the language model is then optimised (for example with PPO) to earn high reward, with a penalty for drifting too far from the SFT model. This recipe was popularised by OpenAI’s InstructGPT (2022), the precursor to ChatGPT.
  • Direct preference optimisation (DPO) (2023) reaches a similar goal without a separate reward model, by training directly on the preferred-versus-rejected pairs. RLAIF and Anthropic’s Constitutional AI use AI feedback guided by written principles to scale up preference data.
  • Reasoning training: newer models are also trained with reinforcement learning on tasks with checkable answers (maths, code that must pass tests), which encourages long step-by-step reasoning before answering.

Parameter-efficient fine-tuning: LoRA

Fine-tuning every weight of a multi-billion-parameter model is expensive and produces a full copy per task. LoRA (low-rank adaptation, 2021) freezes the original weight matrix W and learns a small correction as the product of two thin matrices, W′ = W + B·A.

Common misconception

Fine-tuning is a poor way to teach a model new facts (your product catalogue, this week’s policy). It is good at teaching style, format and behaviour. For facts that change, use retrieval (4.4), which is cheaper to update and lets the answer cite its source.

4.3Prompting: programming in natural language

A prompt is the entire input the model conditions on. Because the model is predicting a likely continuation, the most reliable way to get what you want is to make the desired output the most likely continuation. Principles that follow directly from that:

  1. Be specific about the task, audience and format. “Summarise this for a CFO in five bullet points with numbers” beats “summarise this”.
  2. Give context the model cannot know: your goal, constraints, definitions, the data itself.
  3. Show examples (few-shot prompting). Two or three input→output examples set format and tone better than any description.
  4. Ask for reasoning before the answer on multi-step problems (“think step by step”, or the model’s built-in reasoning mode). Each generated token is computation the model can use, so reasoning first gives it more steps to get things right.
  5. Separate instructions from data with clear delimiters such as XML-style tags, and ask for structured output (JSON with a given schema) when software will read the result.
  6. Use the system prompt for durable rules and role, and the user turn for the specific request.
Going deeper

Treat prompts like code: version them, keep a test set of inputs with expected properties, and measure changes instead of eyeballing one example. The same prompt can behave differently across model versions, so pin model versions in production and re-run your tests when you upgrade.

4.4Retrieval-augmented generation (RAG)

A model only knows what was in its training data, frozen at its cutoff date, and it has never seen your company’s documents. RAG (Lewis et al., 2020) fixes this at question time: find the relevant passages first, then hand them to the model inside the prompt.

Practical lessons that the source reports only hint at:

  • Retrieval is the bottleneck. If the right chunk is not in the top-k, no model can answer correctly. Measure retrieval separately (did the gold passage appear in the top 5?).
  • Hybrid search (vector similarity plus keyword search such as BM25) and a re-ranker model on the top 20–50 results usually beat pure vector search, especially for codes, names and numbers.
  • Chunking matters: split on headings and paragraphs, keep some overlap, and store metadata (source, date, section) so answers can cite and filter.
  • Instruct the model to answer only from the context and to say when the context does not contain the answer. RAG reduces hallucination but, as one report correctly notes, does not eliminate it.

4.5Tools and agents

A language model only emits text, but that text can be a structured request: “call get_weather(city="Oslo")”. With tool use (also called function calling), the application runs the tool and feeds the result back into the context. Loop that, and you have an agent: a model that plans, acts, observes and repeats until a goal is met.

Agents add new failure modes: errors compound over many steps, costs grow with every loop, and any text the agent reads (a web page, an email) can contain prompt injection that tries to hijack it. Good designs keep tools narrowly scoped, require human approval for consequential actions (payments, sending emails, deleting data), and log every step.

4.6Hallucination, from first principles

All four source reports warn about hallucinations, outputs that sound confident but are false. It helps to see why they are not a bug that will simply be patched away:

  1. The objective rewards plausibility, not truth. Pre-training scores “is this a likely next token?”. A fluent, wrong citation is a likely-looking string.
  2. Knowledge is compressed, not stored. Rare facts (a minor paper’s author, an exact figure) are stored weakly and get blended with similar facts.
  3. Sampling adds randomness. Even if the right answer has 70% probability, 30% of the time something else is sampled.
  4. The model often cannot tell what it does not know. Training has historically rewarded answering over abstaining, though newer training explicitly rewards calibrated “I’m not sure”.

Mitigations follow from the causes: ground answers in retrieved sources (RAG) and ask for citations; lower the temperature for factual tasks; let the model use tools for maths, search and code execution; ask it to state uncertainty; verify high-stakes outputs with a person or an independent check; and evaluate on your own data, because hallucination rates vary hugely by domain.

Part V

Generating images: VAEs, GANs and diffusion

Text is a sequence, so “predict the next token” fits naturally. An image is a grid of hundreds of thousands of correlated numbers. Three families of models found three different ways around that.

5.1The problem, and the idea of a latent space

You could generate an image pixel by pixel, autoregressively, and early models (PixelCNN, and the original 2021 DALL·E over compressed image tokens) did something like this. But 786,432 sequential decisions per image is slow, and pixels are highly redundant: neighbouring pixels are nearly always similar.

All three families below lean on one idea: a latent space, a much smaller set of numbers that captures what matters about an image (layout, objects, style) and lets a network fill in the details. Generation then becomes “pick a good point in latent space, then decode it”, or “gradually turn random numbers into a good image”.

5.2Variational autoencoders (VAEs)

An autoencoder squeezes an image through a narrow middle layer and learns to reconstruct it. That alone does not generate: the middle layer’s codes are scattered irregularly, and a random code decodes to garbage. A VAE (Kingma & Welling, 2013) makes the latent space orderly by making the encoder output a distribution (a mean μ and spread σ) and pulling those distributions toward a standard normal.

loss = ‖x − x̂‖² + β · KL( N(μ, σ²) ‖ N(0, I) )reconstruct well, but keep codes close to a simple shared distribution. This is the negative of the evidence lower bound (ELBO).

The reparameterisation trick, z = μ + σ·ε with ε ~ N(0, I), moves the randomness into ε so gradients can flow through μ and σ. VAEs train stably and give smooth, interpolatable latent spaces, but on their own produce slightly blurry images, because averaging over uncertainty blurs fine detail. Their biggest modern role is supporting: Stable Diffusion uses a VAE to compress images into the latent space where diffusion runs.

5.3Generative adversarial networks (GANs)

Ian Goodfellow and colleagues introduced GANs in 2014 with an idea from game theory: train two networks against each other. The generator G turns random noise into a fake sample. The discriminator D tries to tell fakes from real data. G improves by fooling D; D improves by catching G.

minG maxD 𝔼x~data[ log D(x) ] + 𝔼z~N(0,I)[ log(1 − D(G(z))) ]D wants D(real) → 1 and D(fake) → 0; G wants D(fake) → 1

With an ideal discriminator, this game is equivalent to minimising the Jensen–Shannon divergence between the real and generated distributions, so at equilibrium the generator reproduces the data distribution and D outputs ½ everywhere. In practice training alternates one step of D and one step of G, and a few things often go wrong:

  • Mode collapse: G finds a few outputs that fool D and produces only those (every face the same angle), losing diversity.
  • Instability: the two networks oscillate instead of converging; if D becomes too strong, G gets no useful gradient.
  • No likelihood: a GAN cannot score how probable an image is, which makes evaluation harder.

GANs dominated image synthesis from about 2016 to 2021 (StyleGAN’s photorealistic faces are the famous example) and remain useful where speed matters, because generation is a single forward pass. Image enhancement, super-resolution and synthetic data still use them. The source reports also list “deepfake creation” as an application, which is accurate as a description but is primarily a harm (Part VIII).

5.4Diffusion models

Diffusion is the approach behind Stable Diffusion, DALL·E 2 and 3, Imagen and most current image and video generators. Its insight is beautifully simple: destroying an image is easy; learn to undo it one small step at a time.

The forward process

Starting from a real image x₀, add a little Gaussian noise at each of T steps (T = 1000 in the original DDPM paper, 2020). The noise amount per step, βₜ, follows a noise schedule.

q(xₜ | xₜ₋₁) = N( xₜ ; √(1 − βₜ) · xₜ₋₁ , βₜ · I )shrink the image slightly and add fresh noise of variance βₜ

Because adding Gaussians gives a Gaussian, you can jump straight to any step without simulating the ones in between. With αₜ = 1 − βₜ and ᾱₜ = α₁·α₂·…·αₜ:

xₜ = √ᾱₜ · x₀ + √(1 − ᾱₜ) · ε , ε ~ N(0, I)every noisy image is a blend: signal share √ᾱₜ, noise share √(1 − ᾱₜ). As t → T, ᾱₜ → 0 and only noise remains.

The pin screen below shows that blend exactly. Each pin is one pixel; its height is the pixel value of xₜ. Scrub the timestep and watch a picture rise out of noise.

What the network actually learns

Training is remarkably simple. Take a real image, pick a random step t, draw noise ε, build xₜ with the formula above, and ask the network to predict the noise it was given:

L = ‖ ε − εθ( xₜ , t ) ‖²plain mean-squared error between the true noise and the predicted noise, at a random timestep

That is all: no adversary, no instability. Predicting the noise is equivalent to predicting the clean image, and also to estimating the score (the direction in which the image becomes more probable), which links diffusion to score-based models. The network is usually a U-Net (an encoder–decoder convolutional network with skip connections) or, increasingly, a Diffusion Transformer (DiT) that treats the latent as a sequence of patches.

Generating: the reverse process

To sample, start from pure noise xT ~ N(0, I) and repeatedly use the predicted noise to step to a slightly cleaner xₜ₋₁. In DDPM each step also adds a little fresh noise, matching the learned reverse distribution pθ(xₜ₋₁ | xₜ) = N(μθ(xₜ, t), Σ). Faster samplers such as DDIM and DPM-Solver take larger, often deterministic steps, cutting 1000 steps to 20–50 with little loss in quality; distilled models can generate in 1–4 steps.

Latent diffusion and text conditioning

Running diffusion on 512 × 512 × 3 pixels is expensive. Latent diffusion (Rombach et al., 2022, the basis of Stable Diffusion) first compresses images with a VAE by a factor of 8 per side, so diffusion runs on a 64 × 64 × 4 latent, about 48 times fewer numbers.

Text steers the image through cross-attention: queries come from the image latent, keys and values from the text encoder’s token vectors (CLIP in Stable Diffusion 1.x, T5 in Imagen). Prompts are followed much more closely thanks to classifier-free guidance (CFG): the model predicts the noise both with and without the prompt and exaggerates the difference.

ε̂ = εθ(xₜ, ∅) + w · [ εθ(xₜ, prompt) − εθ(xₜ, ∅) ]w = 1 is plain conditioning; w ≈ 5–8 follows the prompt strongly; too high gives over-saturated, distorted images

The same machinery gives image editing for free. Image-to-image adds partial noise to an existing picture and denoises it with a new prompt; inpainting denoises only a masked region; ControlNet-style adapters add conditions such as a pose skeleton or edge map.

Part VI

Audio, video, code and multimodal models

The same two engines, next-token prediction and denoising, applied to sound, moving images and software, plus the trick that connects language to vision.

6.1Audio and speech

Audio is long: one second at 24 kHz is 24,000 numbers, so models rarely generate raw samples one by one (DeepMind’s WaveNet, 2016, did, and was famously slow at first). Two representations make it tractable. A mel spectrogram shows energy per frequency band over time, at about 100 frames a second. A neural audio codec (SoundStream, EnCodec) compresses audio into a few streams of discrete tokens per frame, so audio becomes a token sequence that a language model can predict.

  • Text-to-speech powers audiobooks, accessibility tools, IVR phone systems and multilingual training videos, all use cases the reports list.
  • Speech-to-text (Whisper, an encoder–decoder Transformer) is the other direction, and voice assistants chain recognition → LLM → speech synthesis, or use a single speech-native model.
  • Music generation (Suno, Udio, Google’s Lyria) uses the same token or diffusion approaches on music.
  • Voice cloning is the risk: a few seconds of someone’s voice can be enough, which enables fraud. Consent, disclosure and watermarking are the responsible-use baseline.

6.2Video

Video adds time, and with it the hardest requirement: temporal consistency. An object must keep its shape, colour and identity from frame to frame, and motion must obey something like physics. Current leading systems (OpenAI’s Sora, Google’s Veo, Runway’s Gen series) are diffusion models, typically Diffusion Transformers that cut a compressed video latent into spacetime patches and attend across both space and time. They are very compute-hungry, and they still make tell-tale errors such as objects merging or hands deforming.

6.3Code generation

Code is text, so code models are LLMs trained heavily on source code, documentation and programming Q&A. Three things make code special:

  • Fill-in-the-middle training. Editors need completions in the middle of a file, so code models are trained to fill a gap given the text before and after it.
  • Code can be checked. Unlike prose, code can be compiled, type-checked and tested. That allows the pass@k metric (the chance that at least one of k samples passes the unit tests, introduced with OpenAI’s Codex and the HumanEval benchmark in 2021), and it enables agents that run tests and fix their own errors.
  • Repository context. Real tasks need many files, so coding tools retrieve relevant files, symbols and docs into the context, and agentic tools (GitHub Copilot’s agent mode, Claude Code, OpenAI’s Codex agent, Cursor) edit, run and iterate.

The use cases in the reports hold up: completion, test generation, debugging help, documentation, and modernisation of legacy code. So do the risks: generated code can contain security flaws, invented library functions, or logic that works on the happy path only. Code review, tests and security scanning stay mandatory.

6.4Multimodal models

The bridge between language and vision was CLIP (OpenAI, 2021). It trains an image encoder and a text encoder together on 400 million image–caption pairs so that matching pairs get similar vectors and mismatched pairs get dissimilar ones.

That shared space enables zero-shot image classification, text-to-image search and the text conditioning of image generators. Modern multimodal LLMs go further: a vision encoder (often a Vision Transformer that cuts an image into 14 × 14 or 16 × 16-pixel patches) turns an image into a sequence of vectors that are fed to the language model alongside text tokens. The model can then describe photos, read charts and documents, and reason about screenshots. Some models also output images or audio natively, which is the multimodal future all four reports predict.

7.2Choosing an approach

Most enterprise projects should climb this ladder one rung at a time, stopping at the first rung that meets the quality bar:

  1. Prompting a capable general model, with good instructions and examples.
  2. RAG when answers must come from your own, changing documents.
  3. Tools and agents when the model must act on systems (query a database, file a ticket).
  4. Fine-tuning (often LoRA) when you need a consistent style or format at scale, or a smaller, cheaper model to match a larger one on a narrow task.
  5. Training from scratch, almost never: it costs millions and needs a vast corpus.

Before building, write down how you will measure success (an evaluation set of real inputs with expected outputs or grading criteria), what the cost per request can be, how much latency users will tolerate, and what happens when the model is wrong. As one report rightly says, the real productivity gain depends on implementation quality and on the effort needed to verify outputs.

First principle

Public benchmarks tell you which models to shortlist; only an evaluation built from your inputs, with your definition of a good answer, tells you whether a system is ready. Keep it small but real (50–200 cases), automate what you can, and re-run it on every change of model, prompt or retrieval setting.

Part IX

The pro toolkit

Back-of-the-envelope numbers that let you reason about cost, memory and speed without running anything.

9.1Memory to hold a model

memory for weights ≈ parameters × bytes per parameterFP32 = 4 bytes · FP16/BF16 = 2 · INT8 = 1 · 4-bit = 0.5
7B model in BF16 = 7 × 10⁹ × 2 = 14 GB
7B model in 4-bit = 7 × 10⁹ × 0.5 = 3.5 GB (+ some overhead) → fits a laptop GPU
70B model in BF16 = 140 GB → needs two 80 GB GPUs just for weights

Quantisation stores weights with fewer bits. Well-done 8-bit is nearly lossless and 4-bit usually costs a little quality; it is the main reason capable open models run on consumer hardware. Training needs far more memory than inference: weights, gradients and optimiser state (Adam keeps two extra numbers per weight) come to roughly 16 bytes per parameter in mixed precision, before activations.

9.2Memory for context: the KV cache

KV cache per token = 2 × layers × KV heads × head dimension × bytesthe 2 is one key and one value per head per layer
Llama-2-7B: 32 layers, 32 heads, head dim 128, FP16
per token = 2 × 32 × 32 × 128 × 2 bytes = 524,288 bytes ≈ 0.5 MB
4,096-token context ≈ 2 GB per sequence · 32 users in parallel ≈ 64 GB

This is why long contexts and many simultaneous users are expensive, and why newer models use grouped-query attention (several query heads share one key/value head, cutting the cache 4–8×) and serving systems use paged memory for the cache.

9.3Compute to train and to generate

training compute ≈ 6 × N × D FLOPs generation ≈ 2 × N FLOPs per tokenN = parameters, D = training tokens. Forward pass ≈ 2N per token; the backward pass costs about twice the forward.
7B parameters × 2T tokens: 6 × 7×10⁹ × 2×10¹² = 8.4 × 10²² FLOPs
one GPU at a realistic 400 TFLOP/s = 4×10¹⁴ FLOP/s → 2.1 × 10⁸ s ≈ 6.7 GPU-years
on 1,000 GPUs → about 2.4 days (in practice longer: failures, restarts, data loading)

For generation, the binding limit is usually memory bandwidth, not arithmetic: each new token requires reading every weight from memory once. A 14 GB model on a GPU with ~2 TB/s of bandwidth tops out near 140 tokens per second for one user. Serving systems batch many users together so each weight read is shared.

9.4Architecture and serving tricks worth knowing

  • Mixture of experts (MoE): the feed-forward layer is replaced by many “expert” networks plus a router that sends each token to a few of them. Total parameters can be huge while compute per token stays small.
  • Speculative decoding: a small draft model proposes several tokens; the big model checks them all in one pass and keeps the longest correct prefix. The output distribution is unchanged, and generation is often 2–3× faster.
  • Prompt caching: reuse the KV cache of a long, repeated prefix (a system prompt, a document) across requests to cut cost and latency.
  • Distillation: train a small model to imitate a large one’s outputs; the source of many fast “mini” models.
  • Structured output and constrained decoding: mask out tokens that would break a JSON schema or grammar at each step, so output is always valid.

Part XI

Glossary and self-check

Test yourself. If you can answer these without scrolling up, you understand the field better than most people who use it daily.

11.1Self-check

1. In one sentence, what does a generative model learn that a classifier does not?
The probability distribution of the data itself, p(x), rather than only p(label | x), so it can both score and sample new examples.
2. Your model gives the correct next token a probability of 0.5. What is the cross-entropy loss for that token?
−ln 0.5 ≈ 0.69 nats. If every token looked like that, perplexity would be e^0.69 = 2: like choosing between two equally likely options.
3. Why does a chatbot give different answers to the same question?
Because it samples from the softmax distribution (temperature, top-p) rather than always taking the most likely token. At temperature near 0 it becomes nearly deterministic.
4. What would go wrong if attention scores were not divided by √dₖ?
Dot products would have variance dₖ, so for large heads the softmax would saturate onto one token, and its gradients would become vanishingly small, making training slow or unstable.
5. Why does a decoder need a causal mask during training but an encoder does not?
A decoder is trained to predict each next token; if it could see future tokens, the answer would be in the input. An encoder is trained to understand a complete input (for example, fill in masked words), so seeing both sides is the point.
6. A team wants a support bot to answer from policies that change monthly. Fine-tuning or RAG?
RAG. Facts that change belong in a retrievable store you can update instantly, with citations. Fine-tuning is for style, format and behaviour.
7. In diffusion, at t = 500 with the cosine schedule, √ᾱ ≈ 0.70. What does that mean?
The noisy image is 0.70 × the clean image plus 0.71 × Gaussian noise: signal and noise are about equally strong.
8. What does the denoising network actually predict during training, and what is the loss?
It predicts the noise ε that was added to make xₜ, given xₜ and t. The loss is the mean-squared error ‖ε − ε_θ(xₜ, t)‖².
9. Name the GAN failure where the generator produces only a few kinds of output.
Mode collapse.
10. Why does Stable Diffusion run diffusion in a latent space?
A VAE compresses a 512 × 512 × 3 image into a 64 × 64 × 4 latent (about 48× fewer numbers), so every denoising step is far cheaper while the decoder restores fine detail at the end.
11. Roughly how much GPU memory do the weights of a 13B-parameter model need in BF16? In 4-bit?
13 × 2 = 26 GB in BF16; 13 × 0.5 ≈ 6.5 GB in 4-bit, plus overhead and the KV cache.
12. What is prompt injection, and what is the strongest structural defence?
Malicious instructions hidden in content the model reads (web pages, emails, documents) that try to override its real instructions. Because models cannot reliably tell instructions from data, the strongest defence is limiting what the system can do: least-privilege tools and human approval for consequential actions.

11.2Glossary

Agent
An LLM in a loop that can call tools, observe results and decide next steps toward a goal.
Attention
A learned, soft lookup in which each token blends information from other tokens, weighted by query–key similarity.
Autoregressive
Generating a sequence one element at a time, each conditioned on everything generated so far.
Classifier-free guidance
In diffusion, amplifying the difference between conditional and unconditional noise predictions to follow the prompt more closely.
Context window
The maximum number of tokens a model can take into account at once (prompt plus output).
Cross-entropy
The training loss of language models: the negative log-probability assigned to the correct token.
Diffusion model
A generator that learns to reverse a gradual noising process, turning random noise into data step by step.
Embedding
A learned vector representing a token, passage or image, where similar meaning means nearby vectors.
Fine-tuning
Further training of a pre-trained model on a smaller, targeted dataset.
Foundation model
A large model trained on broad data and adapted to many downstream tasks.
GAN
Generative adversarial network: a generator and a discriminator trained against each other.
Hallucination
Fluent output that is false or unsupported; NIST calls it confabulation.
KV cache
Stored keys and values of earlier tokens, reused so each new token needs only a small computation.
Latent space
A compressed representation in which generation is easier than in raw pixels or samples.
Logit
A raw, unnormalised score for each possible next token, before softmax.
LoRA
Low-rank adaptation: fine-tuning by learning a small product of two thin matrices added to frozen weights.
Perplexity
e raised to the average cross-entropy; roughly the number of options the model is choosing among.
RAG
Retrieval-augmented generation: retrieving relevant documents and placing them in the prompt.
RLHF / DPO
Methods that tune a model toward responses people prefer, with or without a separate reward model.
Softmax
The function that turns a list of scores into positive probabilities summing to one.
Temperature
A divisor on the logits that makes sampling more focused (low) or more varied (high).
Token
The unit a model reads and writes: a word, part of a word, or symbol, mapped to an integer ID.
Transformer
The neural architecture built from attention and feed-forward layers that underlies modern LLMs.
VAE
Variational autoencoder: an encoder–decoder with a smooth, sampleable latent space.
